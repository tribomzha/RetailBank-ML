## **Автоматически выявлять подозрительные операции по счетам — гибрид**

| Поле                            | Что фиксируем                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Бизнес-действие**             | Специалист финмониторинга получает операции в порядке приоритета риска и карточку связанных фактов. Это помогает направлять ограниченное время разбора на наиболее значимые сигналы транзита, обналичивания и дробления платежей.                                                                                                                                              |
| **Объект и единица решения**    | Отдельная операция с историей клиента и контрагентов, доступной на момент оценки. Связанные операции отображаются вместе, чтобы специалист мог проверить предполагаемую цепочку.                                                                                                                                                                                               |
| **Момент**                      | Рабочее допущение первого пилота - пакетная обработка один раз в сутки и теневое сравнение с текущей очередью. Необходимость ответа до исполнения платежа и допустимое время ожидания нужно согласовать с финмониторингом.                                                                                                                                                     |
| **Операция**                    | **Порядок** - ранжирование операций по оценке подозрительности. **Аномалия** — вспомогательное выявление нетипичных сочетаний признаков.                                                                                                                                                                                                                                       |
| **Модальность**                 | **Таблица · время · текст:** суммы, даты, частоты операций, сведения об участниках и назначения платежей. Связи участников формируются из истории операций.                                                                                                                                                                                                                    |
| **Выход модели**                | Числовая оценка подозрительности или аномальности операции, используемая для ранжирования. Эта оценка сама по себе не является вероятностью доказанной схемы.                                                                                                                                                                                                                  |
| **Бизнес-выход**                | Очередь проверки и карточка наблюдаемых фактов со ссылками на операции. Уполномоченный сотрудник принимает решение о запросе документов, расследовании и предусмотренных мерах; обязательные проверки сохраняются независимо от оценки модели.                                                                                                                                 |
| **Источник правильного ответа** | Для оценки полезности очереди - независимый экспертный разбор по единой инструкции; результат доступен после проверки. Исходы расследований и формальные подтверждения учитываются раздельно, последние могут появляться через месяцы. Эскалация не равна подтверждённой схеме, а непроверенная операция не считается чистой; неопределённые случаи получают отдельный статус. |
| **Конвейер**                    | Подготовка истории и признаков **(детерминированно)** → оценка подозрительности **(модель)** → объединение с обязательными приоритетами, сортировка и формирование карточки **(детерминированно)** → разбор **(сотрудник)** → регистрация исходов и дат появления подтверждений **(детерминированно)**.                                                                        |
| **Альтернативные постановки**   | Приоритизация текущих сигналов и поиск новых случаев среди всех операций требуют разных выборок и проверки качества. **Вопросы бизнесу:** первый этап улучшает текущую очередь или должен находить случаи вне действующих правил? Ответ нужен до проведения платежа или для последующего мониторинга?                                                                          |
## **Распознавать и оцифровывать сканы кредитных документов — ML-кандидат**

| Поле                            | Что фиксируем                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Бизнес-действие**             | Сотрудник проверяет и исправляет распознанный текст вместо полной ручной перепечатки. Документы становятся доступны для поиска и последующего извлечения финансовых показателей.                                                                                                                                                                                                               |
| **Объект и единица решения**    | Страница и текстовый блок. Результат собирается в документ, связанный с кредитной заявкой; критичные числа и идентификаторы проверяются как отдельные значения.                                                                                                                                                                                                                                |
| **Момент**                      | После загрузки документов, до содержательного разбора заявки андеррайтером. Для пилота предлагается асинхронная обработка пакета; требуемое время готовности согласуется с владельцем процесса.                                                                                                                                                                                                |
| **Операция**                    | **Извлечение** - распознавание текста, цифр и расположения блоков на изображении.                                                                                                                                                                                                                                                                                                              |
| **Модальность**                 | **Изображение · документ:** PDF-сканы и фотографии страниц кредитного пакета.                                                                                                                                                                                                                                                                                                                  |
| **Выход модели**                | Текстовые блоки с номером страницы и координатами. При поддержке выбранного решения - структура строк и ячеек, оценка уверенности; нечитаемые фрагменты отмечаются как неопределённые.                                                                                                                                                                                                         |
| **Бизнес-выход**                | Электронная копия документа с поиском и привязкой текста к оригиналу, а также список фрагментов для ручной проверки. Принятый текст передаётся в дальнейшую обработку заявки.                                                                                                                                                                                                                  |
| **Источник правильного ответа** | Ручная транскрипция репрезентативных страниц с независимой проверкой сумм, дат и идентификаторов. Эталон становится доступен после сверки и разрешения разногласий, до оценки модели; исправления сотрудников в рабочем процессе дают дополнительную обратную связь.                                                                                                                           |
| **Конвейер**                    | Проверка файла, разделение на страницы и подготовка изображения **(детерминированно)** → распознавание **(OCR-модель)** → сборка документа и привязка блоков к оригиналу **(детерминированно)** → проверка спорных и критичных значений **(сотрудник)** → сохранение принятой версии **(детерминированно)**. Из файлов с настоящим текстовым слоем текст сначала извлекается обычным парсером. |
| **Альтернативные постановки**   | Поисковая копия документа и автоматическое заполнение реквизитов требуют разной точности и разных выходов. **Вопрос бизнесу:** нужен весь распознанный текст или конкретные поля, какие значения можно принимать без проверки и какая ошибка для них допустима?                                                                                                                                |

## **Извлекать финансовые показатели из документов и выписок — гибрид**

| Поле                            | Что фиксируем                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Бизнес-действие**             | Андеррайтер проверяет предварительно заполненную финансовую карточку и разбирает расхождения вместо ручного поиска и переноса каждого показателя. Это сокращает подготовку данных для финансового анализа заявки.                                                                                                                                     |
| **Объект и единица решения**    | Отдельное поле: организация, финансовый показатель, отчётный период, значение, валюта или единица измерения и место в первоисточнике. Принятая карточка объединяет поля по кредитной заявке.                                                                                                                                                          |
| **Момент**                      | После поступления документов и OCR там, где он необходим, до финансового анализа заявки. Обработка запускается по готовности пакета; ответ нужен к моменту работы андеррайтера с финансовой карточкой.                                                                                                                                                |
| **Операция**                    | **Извлечение** - сопоставление фрагментов и таблиц документа с согласованной схемой финансовых показателей. Производные показатели и агрегаты по утверждённым формулам рассчитываются программно.                                                                                                                                                     |
| **Модальность**                 | **Документ · текст · таблица**; для сканов дополнительно используется **изображение** через этап OCR.                                                                                                                                                                                                                                                 |
| **Выход модели**                | Структура «показатель - значение - организация - период - единица/валюта - источник», а также признаки отсутствующих и неоднозначных полей. Для каждого значения сохраняется ссылка на страницу, строку или ячейку.                                                                                                                                   |
| **Бизнес-выход**                | Предварительно заполненная финансовая карточка с приведёнными к согласованным единицам значениями и списком несоответствий. Андеррайтер проверяет и принимает карточку перед использованием в кредитном процессе.                                                                                                                                     |
| **Источник правильного ответа** | Независимо заполненные и сверенные андеррайтерами карточки по единой инструкции, со ссылкой на источник каждого значения. Эталон доступен после согласования разметки; в рабочем процессе обратная связь появляется после проверки карточки сотрудником. Эталон подтверждает правильность извлечения из документа, но не истинность самой отчётности. |
| **Конвейер**                    | Разбор нативного файла **(детерминированно)** либо OCR скана **(модель из №2)** → смысловое извлечение **(модель №18)** → проверки типов, организации, периода, валюты, масштаба и контрольных соотношений **(детерминированно)** → разбор неоднозначностей и принятие карточки **(сотрудник)** → производные расчёты **(детерминированно)**.         |
| **Альтернативные постановки**   | Извлечение значения из строки, вычисление показателя и проверка достоверности отчётности- разные задачи. <br>**Вопрос бизнесу:** какие показатели нужно извлечь буквально, какие вычислить и какие проверить по независимому источнику?                                                                                                               |
